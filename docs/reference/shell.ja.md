# シェルとコマンド

[English](shell.md)

シェル `sh`（`bash`・`dash` という名前でもインストールされています）と、カーネルに組み込まれたコマンドライン
プログラムすべての仕様です。パーサが受け付ける文法、展開、リダイレクト、組み込みコマンド、オプション、
終了ステータス、対話モードと、各プログラムのオプションおよび GNU coreutils との違いを説明します。

## 概要

このページのシェルとプログラムは*カーネルのプログラム*です。カーネルの worker の中で動く TypeScript の関数で、
別の Web Worker ではありません。自分の worker で動くのは `node`（と、それが起動するもの）だけです
（[プロセス](processes.ja.md) と [Node.js ランタイム](nodejs-runtime.ja.md) を参照）。カーネルのプログラムも
本物のプロセスです。pid・親・ファイル記述子・環境変数・終了ステータスを持ち、`ps` に表示されます。

| 項目 | 値 |
|---|---|
| ソース | `src/kernel/sh/parse.ts`（パーサ）、`interp.ts`（インタプリタ・組み込みコマンド・行編集）、`arith.ts`、`pattern.ts`、`printf.ts`、`test.ts`。プログラムは `src/kernel/coreutils.ts` と `src/kernel/curl.ts` |
| シェルの名前 | `/bin/sh`・`/bin/bash`・`/bin/dash`。どれも同じプログラムです。`bash` は GNU bash ではなく、ここで説明する同じ範囲を受け付けます。 |
| プログラムの配置 | 各プログラムは、中身が `#!/ov/builtin <name>` の実行可能なファイル（モード `0755`）です。カーネルはこのインタプリタ行を見分けて、組み込みの関数を実行します。 |
| 場所 | シェルと coreutils は `/bin`。`curl`・`wget`・`env`（`#!/usr/bin/env` の行のためのもう 1 つのコピー）・`node`・`nodejs`（`node` へのシンボリックリンク）・`npm`・`npx`・`pnpm`・`pnpx`・`yarn`・`bun`・`bunx`・`corepack` は `/usr/bin` |
| 既定の `PATH` | `/usr/local/bin:/usr/bin:/bin` |
| `vessel.exec(line)` | `/bin/sh -c <line>` を実行し、`{ code, output }` で解決します（[ホスト API](host-api.ja.md) を参照） |
| 端末 | `vessel.spawn('sh', [], { terminal: { cols, rows } })` で `sh` の fd 0〜2 が TTY になり、対話モードになります |

ホストが起動したプロセスは、カーネルの既定の環境変数に `env` オプションを重ねたものを受け取ります。作業
ディレクトリは `cwd` を指定しなければ `/home/user` です（無ければ作ります）。既定の環境変数は次のとおりです。

| 変数 | 値 |
|---|---|
| `PATH` | `/usr/local/bin:/usr/bin:/bin` |
| `HOME` | `/home/user` |
| `USER`、`LOGNAME` | `user` |
| `SHELL` | `/bin/sh` |
| `TERM` | `xterm-256color` |
| `LANG` | `en_US.UTF-8` |
| `TMPDIR` | `/tmp` |
| `HOSTNAME` | `openvessel` |
| `NAPI_RS_FORCE_WASI` | `true` |

## sh の起動

```text
sh [options] [-c command [name [arg...]]]
sh [options] script [arg...]
sh [options]                     # 標準入力からコマンドを読む。TTY なら対話モード
```

オプションは左から順に、次のどれでもない引数が来るまで読みます。

| オプション | 効果 |
|---|---|
| `-c command` | `command` を実行します。オプションの読み取りはここで終わります。次の引数が `$0`（既定は `sh`）、残りが `$1`… になります。 |
| `-i` | 標準入力が TTY でなくても対話モードにします。 |
| `-e`・`-u`・`-x`・`-f`・`-a` と `+` の形 | `set` と同じです（[シェルのオプション](#シェルのオプション) を参照）。複数の文字をまとめられ、`c`・`i`・`o` とも組み合わせられます（`-eu`、`+ex`、`-ec '…'`、`-eo pipefail`）。 |
| `-o name`、`+o name` | `set -o name` / `set +o name` と同じです。 |
| `-l`、`--login`、`--norc`、`--noprofile`、`-s` | 受け付けて無視します。 |
| `--` | オプションの終わりです。 |

それ以外（`--version` も含む）はスクリプトのファイル名として扱います。

何を実行するかは次のように決まります。

| 状況 | 動作 |
|---|---|
| `-c` がある | 文字列を解析して実行します。終了ステータスは最後のコマンドのものです。 |
| スクリプトの引数がある | ファイルを読みます（作業ディレクトリから見た相対パス。`PATH` は探しません）。1 行目が `#!` で始まっていれば捨てます。`$0` は渡されたとおりのファイル名、`$1`… は残りの引数です。ファイルが無いと `sh: <file>: No such file or directory` を出し、127 で終わります。 |
| 引数なし・標準入力が TTY でない・`-i` なし | 標準入力をすべて読んでから、1 つのスクリプトとして解析して実行します。 |
| 引数なしで標準入力が TTY、または `-i` | `$HOME/.shrc` を実行し（エラーは無視）、対話のループに入ります（[対話モード](#対話モード) を参照）。 |

`/home/user/.shrc` は起動時に次の内容で作られます。

```sh
alias ll='ls -l'
alias la='ls -la'
```

`.shrc` を読むのは対話シェルだけなので、`sh -c` やスクリプトにはこの別名がありません。

入力は bash と同じく、完結したコマンド（ふつうは 1 行）ごとに解析して実行します。構文エラーは
`<name>: <message>`（`<name>` は `$0` かスクリプトの名前）と表示され、ステータス 2 で止まります。それより前の行は
すでに動いています。

## 文法

パーサ（`src/kernel/sh/parse.ts`）は、POSIX シェルの文法の実用的な部分に、bash の拡張をいくつか加えたものです。
完結したコマンド（その行の終わりまで。複合コマンドは複数の行にまたがれます）を 1 つ解析して実行してから、
次を解析します。

### リストとパイプライン

| 構文 | 意味 |
|---|---|
| `a ; b`、改行 | `a` を実行し、次に `b` を実行します。 |
| `a & b` | `a` をバックグラウンドで実行し（[バックグラウンドとサブシェル](#バックグラウンドとサブシェル) を参照）、次に `b` を実行します。 |
| `a && b` | `a` が 0 で終わったときだけ `b` を実行します。 |
| `a \|\| b` | `a` が 0 以外で終わったときだけ `b` を実行します。 |
| `a \| b` | パイプライン。`a` の標準出力が `b` の標準入力になります。要素は並行に動きます。 |
| `a \|& b` | 同じですが、`a` の標準エラー出力もパイプに入ります（`a 2>&1 \| b` の略記）。 |
| `! pipeline` | 終了ステータスを反転します（0 は 1 に、それ以外は 0 に）。`!` の後には空白が必要です。 |

`&&` と `||` は同じ優先順位で、左から結合します。`|`・`&&`・`||` の後には改行を置けます（次の行に続きます）。
シングルクォートの外では、`\` と改行の組は取り除かれます（行の継続）。単語の先頭の `#` から行末まではコメントです。

### 複合コマンド

| 構文 | 説明 |
|---|---|
| `{ list; }` | 中かっこのグループ。今のシェルで動きます。`{` と `}` は予約語なので、独立した単語でなければならず、`}` はコマンドの先頭（`;` か改行の後）に置きます。 |
| `( list )` | サブシェル。シェルの状態（変数・関数・別名・オプション・作業ディレクトリ・fd）のコピーで動きます。変更は親に届きません。 |
| `if list; then list; [elif list; then list;]... [else list;] fi` | |
| `while list; do list; done` | |
| `until list; do list; done` | |
| `for name [in word...]; do list; done` | `in` が無ければ `"$@"` を回します。単語はすべての展開（分割とグロブも）を受けます。 |
| `case word in [(]pattern[\|pattern]...) list ;; ... esac` | シェルのパターンです（[パターン照合](#パターン照合) を参照）。最初に合った項目を実行します。どれにも合わなければステータスは 0 です。`esac` の前の最後の `;;` は省けます。項目は `;&`（次の項目のリストも、パターンを調べずに実行する）や `;;&`（続くパターンを調べ続ける）で終えることもできます。 |
| `(( expression ))` | 算術のコマンド。式が 0 以外ならステータス 0、そうでなければ 1 です。中身はまずダブルクォートの文字列と同じように展開されます。 |
| `[[ expression ]]` | 条件のコマンド（[条件コマンド](#条件コマンド) を参照）。 |

どの複合コマンドの後にもリダイレクトを書けます（`while ...; done < file`、`{ ...; } 2>&1`）。

### 関数

```sh
name() compound-command
function name compound-command
function name() compound-command
```

- `name()` の形では、`name` はそのままの文字の単語でなければなりません。`function` を使う形では、名前に英字・
  数字・`_`・`.`・`:`・`-` を使えます（先頭は英字か `_`）。
- 本体はどのコマンドでもかまいません。ふつうは `{ ...; }` のグループです。
- 関数を呼ぶと、その間だけ `$1`… と `$#` が変わり（`$0` は変わりません）、終わると元に戻ります。`local` と
  `declare` の変数は関数から戻るときに元に戻ります。
- `return [n]` はステータス `n & 255`（既定は直前のステータス）で関数を抜けます。
- 呼び出しが 200 段より深くなると `maximum function nesting level exceeded` で失敗します。
- コマンド名を探す順番は、関数、組み込みコマンド、プログラムのファイルです（[コマンドの探し方](#コマンドの探し方) を参照）。

### 予約語

`if then else elif fi do done case esac while until for in { } ! function [[ ]]` は、コマンドの位置でだけ
予約語になります（`in` と `do` は文法がそれを待つ位置で）。`select`・`coproc`・`time` は予約語ではありません
（`time` はプログラムです。[time と timeout](#time-と-timeout) を参照）。

### 対応していないもの

パーサとインタプリタで確かめたものです。

| 機能 | どうなるか |
|---|---|
| 中かっこの展開 `{a,b}`、`{1..3}` | 行いません。単語はそのまま残ります（`echo {a,b}` は `{a,b}` を出力）。 |
| プロセス置換 `<(cmd)`、`>(cmd)` | 構文エラー: `syntax error near unexpected token '('`。 |
| 配列 | `name=(a b c)` は、かっこの中の文字列（最初の `)` まで。前後の空白を除き、クォートは処理しない）を 1 つの文字列として持ちます。`${name[i]}` は添字を無視します。`name+=(x)` は区切りなしで文字列を足します。例外は `BASH_REMATCH` だけです。 |
| 間接展開 `${!name}` | `bad substitution`（構文エラー、ステータス 2）。 |
| `${parameter@op}`、`${!prefix*}` | `bad substitution`。 |
| 拡張グロブ `@(…)`、`!(…)`、`+(…)` | 構文エラー。`(` は単語の中でメタ文字です。 |
| ジョブ制御 | `fg`・`bg` はありません（command not found）。`jobs` は何も出力しません。 |
| `PS2` | 続きの行のプロンプトは常に `> ` です。 |

## クォート

| 形 | 意味 |
|---|---|
| `'...'` | そのままの文字列です。特別な文字はありません。中に `'` は書けません。 |
| `"..."` | `$`・`` ` ``・`\` は特別なままです。`\` がエスケープするのは `$`・`` ` ``・`"`・`\`・改行（取り除かれる）だけで、ほかの文字の前ではそのまま残ります。 |
| `\c`（クォートの外） | 次の 1 文字をクォートします。`\` と改行の組は行の継続です。 |
| `$'...'` | ANSI-C のクォート。エスケープは `\a` `\b` `\f` `\n` `\r` `\t` `\v`・`\e`/`\E`（ESC）・`\nnn`（8 進 1〜3 桁）・`\xHH`（16 進 1〜2 桁）・`\uHHHH`（16 進 1〜4 桁）・`\UHHHHHHHH`（16 進 1〜8 桁）・`\cX`（制御文字）です。それ以外の `\c` は `c` になります（`\\` → `\`、`\'` → `'`）。 |

クォートされた文字列は、分割もグロブもされません。空のクォート（`""`、`''`）は空の単語を 1 つ作ります。

## 展開

単純なコマンドの各単語は、次の順に展開されます。チルダ、パラメータ・コマンド置換・算術（左から順に）、
クォートされていない結果の単語分割、クォートされていないグロブ文字を含む単語のパス名展開、クォートの除去です。
代入の値、リダイレクトの対象、`case` の単語、`[[ ]]` の中の単語は、単語分割もグロブもせずに展開します。

別名の置き換えはそれより前、コマンドを解析するときに行います（[別名](#別名) を参照）。

### チルダ展開

単語の先頭の `~` の後が、単語の終わり・`/`・メタ文字のとき、置き換えます。

| 形 | 結果 |
|---|---|
| `~` | `$HOME`（設定されていなければ `/home/user`） |
| `~root` | `/root` |
| `~name` | `/home/name`（パスワードファイルは見ません） |

結果は分割もグロブもされません。`~+` と `~-` には対応していません。展開されるのは単語の先頭の `~` だけです
（`PATH=~/bin` は展開され、`a:~/b` の 2 つ目の `~` は展開されません）。

### パラメータと変数

変数名は `[A-Za-z_][A-Za-z0-9_]*` です。`$name` は、この形でいちばん長い名前を取ります。`$1`〜`$9` は 1 桁だけ
取ります（`$10` は `$1` の後に `0`）。10 番目以降は `${10}` と書きます。

特別なパラメータ:

| パラメータ | 値 |
|---|---|
| `$?` | 直前のコマンドのステータス。 |
| `$$` | シェルのプロセスの pid。サブシェル・パイプラインの要素・コマンド置換は同じプロセスの中で動き、バックグラウンドのジョブ（別のプロセス）も bash と同じく親の `$$` を持ちます。 |
| `$!` | 最後のバックグラウンドのジョブのプロセスの pid。`kill` にも `wait` にも使えます。最初の `&` の前は空です。 |
| `$#` | 位置パラメータの数。 |
| `$0` | シェルかスクリプトの名前（`sh`、`-c` の名前の引数、またはスクリプトのパス）。 |
| `$1`… | 位置パラメータ。 |
| `$@`、`$*` | すべての位置パラメータ（[単語分割](#単語分割) を参照）。 |
| `$-` | 今のオプションの文字。`e`・`x`・`u`・`i` から（この順で）。`f`・`a`・`pipefail` は表示されません。 |

シェルが設定する、または読む変数:

| 変数 | 意味 |
|---|---|
| `PWD` | 今のディレクトリ。常にシェルの作業ディレクトリを表し、エクスポートされます。`PWD` に代入すると、シェルの作業ディレクトリの認識が変わります。 |
| `OLDPWD` | 前のディレクトリ。`cd` が設定し、エクスポートします。 |
| `PPID` | シェルのプロセスの親の pid。 |
| `IFS` | 単語の区切り文字。既定は空白・タブ・改行。エクスポートされません。 |
| `HOME` | `~`、引数なしの `cd`、プロンプトの `~`、`.shrc` に使います。 |
| `PATH` | プログラムを探すパス（`source`・`type`・`command -v`・`which`・タブ補完でも使います）。 |
| `CDPATH` | `cd` が、`.` で始まらない相対の名前を探すディレクトリ（コロン区切り）。 |
| `RANDOM` | 読むたびに 0〜32767 の新しい乱数。 |
| `SECONDS` | シェルのプロセスが始まってからの秒数（整数）。 |
| `PS1` | 対話モードのプロンプト（[プロンプト](#プロンプト) を参照）。 |
| `PS4` | `set -x` のトレース行の前に付く文字列。既定は `+ `。 |
| `REPLY` | `read` の既定の変数。 |
| `OPTIND`、`OPTARG` | `getopts` が使います。 |
| `BASH_REMATCH` | `[[ string =~ regex ]]` が設定します。`$BASH_REMATCH` と `${BASH_REMATCH[0]}` は合った部分全体、`${BASH_REMATCH[n]}` は n 番目のグループ、`${#BASH_REMATCH[@]}` は要素の数です。 |
| `__OV_OPTSUB`、`__OV_DIRSTACK` | `getopts` と `pushd`/`popd` の内部の状態（`set` で見えます）。 |

代入:

- `name=value` と `name+=value`（今の値に足す）。コマンドの前に複数置けます。
- コマンドの単語が無いときは、今のシェルで代入します。ステータスは、その代入の中の最後のコマンド置換のもので、
  無ければ 0 です（`x=$(false); y=1` の `y=1` は 0）。
- 外部のプログラムの前に置くと、そのプログラムの環境変数にだけ入ります。
- 関数やふつうの組み込みコマンドの前に置くと、呼び出しの間だけ設定され、その後元に戻ります。
- 特別な組み込みコマンド（`:` `.` `break` `continue` `eval` `exec` `exit` `export` `readonly` `return` `set`
  `shift` `trap` `unset` `source`）の前に置くと、設定されたまま残ります。
- `readonly` の変数に代入すると `sh: <name>: readonly variable` を出し、ステータスは 1 です。代入だけのコマンドでは
  今の行の残りを飛ばし、次の行に進みます（bash と同じ。対話シェルは次のプロンプトを出します）。組み込みコマンド
  （`export`・`read` など）の中では、そのコマンドがステータス 1 で失敗します。

### パラメータ展開

以下の `parameter` は、名前、位置の番号、または `@ * # ? $ ! -` のどれかです。

| 形 | 結果 |
|---|---|
| `${parameter}` | 値。 |
| `${#parameter}` | 長さ（UTF-16 のコード単位の数）。`${#@}` と `${#*}` は位置パラメータの数です。 |
| `${p:-word}` / `${p-word}` | `p` が未設定か空 / 未設定なら `word`。そうでなければ値。 |
| `${p:=word}` / `${p=word}` | 同じで、さらに `p` に `word` を代入します。 |
| `${p:?word}` / `${p?word}` | 未設定か空 / 未設定なら、`sh: p: word`（または `sh: p: parameter null or not set`）を出して、対話でないシェルをステータス 1 で終わらせます。対話シェルは終わらず、そのコマンド行をステータス 1 でやめます。 |
| `${p:+word}` / `${p+word}` | `p` が設定されていて空でない / 設定されているなら `word`。そうでなければ空。 |
| `${p#pattern}` / `${p##pattern}` | 先頭から、合う部分の最短 / 最長を取り除きます。 |
| `${p%pattern}` / `${p%%pattern}` | 末尾から、合う部分の最短 / 最長を取り除きます。 |
| `${p/pattern/string}` | 最初に合った部分を置き換えます（いちばん左の位置での最長一致）。 |
| `${p//pattern/string}` | 合った部分をすべて置き換えます。 |
| `${p/#pattern/string}` / `${p/%pattern/string}` | 先頭 / 末尾に固定した一致を置き換えます。 |
| `${p^}` / `${p^^}` | 最初の文字 / すべての文字を大文字にします。パターンの引数は無視します。 |
| `${p,}` / `${p,,}` | 最初の文字 / すべての文字を小文字にします。 |
| `${p:offset}` / `${p:offset:length}` | 部分文字列。負の offset は末尾から数えます（`${p: -3}` と書きます。`${p:-3}` は既定値の形です）。負の length は、末尾からその文字数手前で終わります。offset と length は展開後に `Number()` で変換します。算術式ではなく、数でなければ 0 です。`@`/`*` では、パラメータの切り出しではなく、つないだ文字列の部分文字列になります。 |
| `${name[index]}` | 添字は無視します。`${name}` と同じです。 |

`#`・`%`・`/` の形のパターンはシェルのパターンで、クォートした部分は文字どおりに照合します。`word` には
ふつうの展開が行われます。`set -u` のとき、未設定の変数（特別なパラメータを除く）を展開すると
`sh: name: unbound variable` を出し、対話でないシェルはステータス 1 で終わります（対話シェルはそのコマンド行をやめます）。

### コマンド置換

`$(commands)` と `` `commands` `` は、シェルのコピー（同じプロセスの中）でコマンドを実行し、標準出力を取り込みます。
末尾の改行は取り除きます。クォートしなければ、結果は単語分割とグロブを受けます。`$?` は置換のステータスになります。
バッククォートの中では、解析の前に `\$`・`` \` ``・`\\` のエスケープを外します。`$((` は常に算術展開の始まりです。

### 算術展開

`$(( expression ))` は 10 進の値に置き換わります。式はまずダブルクォートの文字列と同じように展開され（`$x` や
`$(cmd)` が使えます）、その後 `src/kernel/sh/arith.ts` で計算されます。

オペランド:

| オペランド | 例 |
|---|---|
| 10 進 | `42` |
| 8 進（先頭が `0`） | `010` = 8。`08` はエラー |
| 16 進 | `0x1f` |
| `base#digits`（基数 2〜64） | `2#101` = 5、`36#z` = 35。36 を超えると数字は `0-9a-zA-Z@_`（`64#_` = 63） |
| 変数名 | 未設定か空なら 0。値が数でなければ式として計算します。値が変数名なら、それをたどります（8 段まで）。 |

演算子（優先順位の高い順）:

| 演算子 | 説明 |
|---|---|
| `( )` | グループ |
| `x++ x--` `++x --x` | 変数にだけ使えます |
| `+ - ! ~`（単項） | |
| `**` | 右結合 |
| `* / %` | `/` は 0 の方向に切り捨て。0 による `/` と `%` は `division by 0` で失敗 |
| `+ -` | |
| `<< >>` | |
| `< <= > >=` | 結果は 1 か 0 |
| `== !=` | |
| `&` | |
| `^` | |
| `\|` | |
| `&&` | 左辺が 0 以外のときだけ右辺を計算します |
| `\|\|` | 左辺が 0 のときだけ右辺を計算します |
| `?:` | 選ばれた側だけを計算します |
| `= += -= *= /= %= <<= >>= &= ^= \|= **=` | 変数への代入 |
| `,` | 最後の式の値 |

計算は bash と同じく、オーバーフローするとラップアラウンドする 64 ビットの符号付き整数です。`9223372036854775807+1` と `2**63` は
`-9223372036854775808`、`2147483647*2` = `4294967294`、`1<<33` = `8589934592` です。

`$(( ))` の中のエラー（構文エラー、0 による割り算）は `sh: <expression>: <message>` と表示し、ステータスを 1 に
して今の行の残りを飛ばします（シェルは次の行に進みます）。`(( ))` では `sh: ((: <message>` と表示し、コマンドが
1 を返します。`let` では `sh: let: <expression>: <message>` と表示し、`let` が 1 を返します。

### 単語分割

クォートされていないパラメータ展開・コマンド置換・算術展開の結果は、`IFS` の文字で単語に分けられます（既定は
空白・タブ・改行。`IFS` が未設定なら既定と同じ）。

- IFS の空白（空白・タブ・改行）の並びは単語を区切り、両端では取り除かれます。
- それ以外の IFS の文字は 1 つごとに単語を終わらせるので、続けて並ぶと空の単語ができます（`IFS=:` で `a::b` は
  `a`、空、`b`）。
- `IFS=''` で分割しなくなります。
- 同じ単語の中でクォートされていた部分は分割されません。

`"$@"` は位置パラメータ 1 つにつき 1 単語に展開されます（無ければ何も無し）。`"$*"` は `IFS` の最初の文字で
つないだ 1 単語です（`IFS` が空なら区切りなし）。クォートしない `$@` と `$*` は、パラメータ 1 つにつき 1 単語に
なり、それぞれがさらに分割されます。

### パス名展開

分割の後、クォートされていない `*`・`?`・`[` を含む単語を、ファイルシステムと照合します。照合はパスの要素ごとです。

| パターン | 合うもの |
|---|---|
| `*` | `/` を含まない任意の文字列 |
| `?` | `/` 以外の任意の 1 文字 |
| `[abc]`、`[a-z]` | 集合の中の 1 文字 |
| `[!abc]`、`[^abc]` | 集合に無い 1 文字 |
| `[[:class:]]` | `alpha`・`digit`・`alnum`・`upper`・`lower`・`space`・`blank`・`punct`・`xdigit`・`word` |
| `**`（要素全体） | 0 個以上のディレクトリ、深さは任意（`.` で始まるディレクトリは飛ばします） |
| `\c` やクォートした文字 | その文字そのもの |

- `.` で始まる名前は、パターンの要素が `.` で始まるときだけ合います。`.` と `..` は `readdir` に出てこないので、
  合うことはありません。
- 結果は並べ替えられます（UTF-16 のコード単位の順）。`/` で終わるパターンはディレクトリ（とディレクトリへの
  シンボリックリンク）にだけ合い、`/` を付けて並べます（`*/` は `d1/`）。
- 何も合わなければ、単語はそのまま残ります（`echo *.nomatch` は `*.nomatch` を出力）。`nullglob`・`failglob` はありません。
- `set -f`（または `set -o noglob`）でパス名展開をしなくなります。

### パターン照合

`case`、`[[ x == pattern ]]`、パラメータ展開の `#`/`%`/`/` の形は、グロブと同じパターンの書き方を使います。
ただし `*` と `?` は `/` にも合い、先頭のドットも特別扱いしません。閉じる `]` の無い `[` は、`[` そのものに合います。

### 別名

`alias name=value` で別名を定義します。コマンドを解析するとき、コマンドの位置にあるクォートされていない単語が
別名なら、その値で置き換えて、そこから解析を続けます。このため次のようになります。

- 値には文法で書けるものなら何でも入れられます。複数のコマンド（`alias x='a; b'`）、パイプ（`alias y='sort |'`）、
  予約語も使えます。
- 別名は自分の値の中では再び展開されません。値が空白で終わると、次の単語も別名かどうか調べます。
- 行は実行する前に解析するので、ある行で定義した別名は次の行から効きます（同じ行の `alias x=…; x` では使われません）。
  bash と同じです。スクリプトや `sh -c` でも別名を展開します（POSIX の sh と同じ。bash ではそこで
  `shopt -s expand_aliases` が要ります）。
- `$HOME/.shrc` で定義した別名（既定では `ll` と `la`）は対話シェルにだけあります。

## リダイレクト

リダイレクトの前には、1 桁のファイル記述子の番号（`0`〜`9`）を、演算子の直前に書けます（`2>`）。リダイレクトは
左から順に適用します。対象の単語は、分割もグロブもせずに展開します（`> *.txt` は `*.txt` という名前のファイルを作ります）。

| 演算子 | 既定の fd | 効果 |
|---|---|---|
| `< file` | 0 | 読み込み用に開く |
| `> file` | 1 | 書き込み用に開く。作成し、切り詰める |
| `>\| file` | 1 | `>` と同じ（`noclobber` はありません） |
| `>> file` | 1 | 追記用に開く。作成する |
| `<> file` | 0 | 読み書き用に開く。作成する（切り詰めない） |
| `&> file`、`>& file` | 1 と 2 | 標準出力と標準エラー出力をファイルへ（切り詰める） |
| `&>> file` | 1 と 2 | 標準出力と標準エラー出力をファイルに追記 |
| `n>&m`、`n<&m` | 1 / 0 | `n` を `m` の複製にする |
| `n>&-`、`n<&-` | 1 / 0 | `n` を閉じる |
| `<< word`、`<<- word` | 0 | ヒアドキュメント |
| `<<< word` | 0 | ヒアストリング。展開した単語に改行を付けたもの |

エラーのときは `sh: <target>: No such file or directory`（または `Is a directory`、`Permission denied`、閉じた
fd の複製なら `<n>: Bad file descriptor`）を出し、コマンドは実行されずにステータス 1 で失敗します。数でない単語への
`n<&word` は `ambiguous redirect` です。

コマンドの無い `exec` にリダイレクトを付けると、シェル自身にずっと適用されます。

```sh
exec 3>/tmp/log      # fd 3 を開く
echo hello >&3
exec 3>&-            # 閉じる
exec 2>/dev/null     # スクリプトの残りで標準エラー出力を捨てる
```

### ヒアドキュメント

```sh
cat <<EOF
home is $HOME, today is $(date +%F)
EOF

cat <<'EOF'
nothing is expanded: $HOME `cmd`
EOF

cat <<-EOF
	leading tabs are removed from each line and from the delimiter line
	EOF
```

- 本文はコマンドの次の行から始まり、区切りの単語と同じ行で終わります。1 行に複数のヒアドキュメントがあれば、
  順に読みます。入力の終わりに来たら、本文はそこで終わります。
- 区切りの単語のどこかがクォートされていれば（`'EOF'`、`"EOF"`、`\EOF`、`E"O"F`）、本文はそのままです。そうで
  なければパラメータ展開・コマンド置換・算術展開を行い、`\` は `$`・`` ` ``・`\`・改行をエスケープします
  （ダブルクォートの中と同じ）。
- `<<-` は行頭のタブを取り除きます（空白は取り除きません）。
- 本文はコマンドが始まる前にパイプに書かれます。大きさの上限はありません。

## 条件式

### test コマンド

`test expr` と `[ expr ]`（組み込みコマンド。`/bin/test` と `/bin/[` にもあります）は次を評価します。

| 式 | 真になる条件 |
|---|---|
| `-e f`、`-a f` | `f` がある |
| `-f f` | ふつうのファイル |
| `-d f` | ディレクトリ |
| `-L f`、`-h f` | シンボリックリンク（たどらない） |
| `-p f` | FIFO |
| `-c f` | キャラクタデバイス |
| `-s f` | 大きさが 0 より大きい |
| `-S f`、`-b f` | ソケット、ブロックデバイス |
| `-r f`、`-w f`、`-x f` | uid 1000 に読み / 書き / 実行の権限がある（所有者・グループ・その他のうち当てはまるビット） |
| `-u f`、`-g f`、`-k f` | setuid・setgid・スティッキーのビットが立っている |
| `-O f`、`-G f` | uid / gid 1000 のもの |
| `-N f` | 最後に読まれてから変更された（mtime が atime より後） |
| `-o name` | シェルのオプション `name` がオン |
| `-t fd` | `fd` が TTY |
| `-z s` / `-n s` | `s` が空 / 空でない |
| `-v name` | 変数 `name` が設定されている |
| `s` | `s` が空でない |
| `a = b`、`a == b`、`a != b` | 文字列が等しい（パターンではない） |
| `a < b`、`a > b` | 文字列の順（UTF-16）。`[ ]` の中ではクォートします |
| `a -eq/-ne/-lt/-le/-gt/-ge b` | 整数の比較 |
| `a -nt b` / `a -ot b` | 更新時刻が新しい / 古い（無いファイルはいちばん古いものとして扱う） |
| `a -ef b` | 同じ inode |
| `! e`、`e1 -a e2`、`e1 -o e2`、`( e )` | 否定・かつ・または・グループ（`-a` は `-o` より強く結合） |

引数なしは偽（1）です。`sh: test: <x>: integer expression expected`、`sh: test: too many arguments`、
`sh: [: missing ']'` はメッセージを出してステータス 2 です。

### 条件コマンド

`[[` と `]]` の間の単語は、分割もグロブもせずに展開します。使えるもの:

| 式 | 意味 |
|---|---|
| `a == pattern`、`a = pattern` | シェルのパターンとの照合。パターンのクォートした部分は文字どおり |
| `a != pattern` | 合わない |
| `a =~ regex` | POSIX の拡張正規表現（ERE）での検索（`[[:digit:]]` などの括弧式も使えます）。正規表現のクォートした部分は文字どおりに照合します（`[[ $v =~ ^a"."b ]]`）。クォートしていない `( ) \| < >` は正規表現の一部で、かっこの中では空白も含みます。`BASH_REMATCH` を設定します。正しくない正規表現はステータス 2 です。 |
| `a < b`、`a > b` | 文字列の順 |
| `-eq -ne -lt -gt -le -ge -nt -ot` | `test` と同じ |
| `test` のすべての単項演算子とオペランド | `test` と同じ |
| `!`、`&&`、`\|\|`、`( )` | 否定・かつ・または・グループ |
| `word` | 空でなければ真 |

未知の単項演算子にオペランドが続くとエラーです（`sh: [[: unexpected argument … to conditional unary
operator`、ステータス 2）。それ以外のステータスは 0 か 1 です。

## コマンドの実行

### コマンドの探し方

単純なコマンドでは、展開と別名の置き換えの後、次の順に探します。

1. 引数の無い `exec`: リダイレクトをシェルに適用します。
2. その名前のシェル関数。
3. 組み込みコマンド（[組み込みコマンド](#組み込みコマンド) を参照）。
4. プログラム: 名前に `/` があれば作業ディレクトリから解決します。無ければ `PATH` の各ディレクトリで、実行の
   ビットのあるふつうのファイルを探します。`PATH` に無くても、名前がカーネルのプログラム（`ls`・`sh`・`npm` など）
   なら、そのプログラムが動きます。

カーネルがプログラムのファイルをどう実行するか（`src/kernel/kernel.ts` の `planExec`）:

| ファイルの先頭 | 動くもの |
|---|---|
| `#!/ov/builtin name` | カーネルのプログラム `name`（`node` なら Node.js のプロセス） |
| `#!/usr/bin/env [-S] [VAR=val...] interp args`（または `/bin/env`） | `PATH` で探した `interp`。`VAR=val` の単語は飛ばします（設定はしません） |
| `#!` とインタプリタ `node`・`nodejs`・`bun`・`deno` | Node.js に、インタプリタの引数とファイルを渡したもの |
| `#!` とそれ以外のインタプリタ | そのインタプリタに、ファイルを引数として渡したもの（8 段まで。それを超えると `ELOOP`） |
| `#!` なしで、名前が `.js`・`.cjs`・`.mjs` で終わる | Node.js にファイルを渡したもの |
| `#!` なしで、それ以外 | `sh file`（POSIX の `ENOEXEC` の扱いと同じ） |

Node.js は移植版ランタイムで起動します。プロセスの起動時に `/etc/openvessel/node` の中身が `legacy` のときだけ、
旧ランタイムを使います。[Node.js ランタイム](nodejs-runtime.ja.md) を参照してください。

### 終了ステータス

| ステータス | 意味 |
|---|---|
| 0〜255 | コマンドの終了ステータス（`exit n` と `return n` は `n & 255` を使うので、`exit 300` は 44） |
| 1 | リダイレクトの失敗、readonly の変数への代入、算術のエラー、`${p:?}`、`set -u` の違反 |
| 2 | 構文エラー、`test`/`[`/`[[`/`printf`/`source` の使い方の誤り |
| 126 | プログラムのファイルはあるが実行できない（`sh: X: Permission denied`）、またはそのほかの起動のエラー |
| 127 | コマンドが見つからない（`sh: X: command not found`）、`sh file` のスクリプトが無い |
| 128 + n | シグナル `n` で終わった: 130 SIGINT、137 SIGKILL、141 SIGPIPE、143 SIGTERM |
| 130 | シェル自身がコマンドの合間に割り込まれた |
| 141 | 組み込みコマンドが、読み手の無いパイプに書いた（EPIPE） |

対話モードでは、プログラムが SIGINT と SIGPIPE 以外のシグナルで終わると、シェルがシグナルの名前（たとえば
`SIGTERM`）を表示します。

### 環境変数

プログラムが受け取るのは、シェルのエクスポートされた変数（環境から受け継いだもの、`export`・`declare -x` で
設定したもの、`set -a` の間に代入したもの）、`PWD`、そしてコマンドの前の代入です。`OLDPWD` は `cd` がエクスポート
します。組み込みコマンドと関数は、すべての変数を見られます。

### バックグラウンドとサブシェル

シェルは、サブシェル・パイプラインの要素・コマンド置換のために、カーネルのプロセスを作りません。どれも同じ
シェルのプロセスの中で、シェルの状態のコピーとして動きます（必要なら並行に）。バックグラウンドのジョブは自分の
プロセスを持ちます。どこから起動したプログラムも別のプロセスです。

- サブシェル `( )`: 中の `exit` はサブシェルだけを終わらせます。
- パイプライン: 各要素はそれぞれのコピーで並行に動きます。ステータスは最後の要素のもの、`set -o pipefail`
  のときは失敗したいちばん右の要素のものです。対話シェルでは、パイプラインは 1 つのジョブです。そのプログラムは
  1 つのプロセスグループに入り、パイプラインが動いている間はそのグループが端末の前面のグループになります。対話で
  ないシェルでは、プログラムはシェルのプロセスグループに残るので、グループに送られた ^C が届きます。パイプライン
  の要素の中の `exit` は、その要素だけを終わらせます。
- バックグラウンド `&`: コマンドは新しいプロセス（シェルのコピー）で動き（プログラムを指す単純なコマンドは
  そのプロセスで直接実行します）、シェルはすぐにステータス 0 で先に進みます。標準入力はリダイレクトしません。
  `$!` はそのプロセスの pid なので、`kill $!` が使えます。`wait`（引数なし）はすべてのバックグラウンドのジョブを
  待って 0 を返します。`wait PID` はそのジョブを待ってステータスを返します。すでに終わっていても返します。
  ステータスを受け取れるのは 1 回だけで、同じ pid（またはこのシェルの子でない pid）でもう一度 `wait` すると
  `sh: wait: pid N is not a child of this shell` を出して 127 を返します。trap したシグナルが届くと、`wait` は
  128 + シグナル番号で中断します。

```sh
npm run build > build.log 2>&1 &
job=$!
echo "building..."
wait "$job"; echo "build exited with $?"
```

## シェルのオプション

`set [-+]letters`、`set -o name` / `set +o name`、または `sh` のコマンドラインの同じフラグで設定します。

| 文字 | `-o` の名前 | 効果 |
|---|---|---|
| `-e` | `errexit` | コマンドが失敗したら終わります。`if`/`elif`/`while`/`until` の条件、`&&`/`\|\|` のリストの最後以外のコマンド、`!` のパイプラインには適用しません。関数の中には適用します。 |
| `-u` | `nounset` | 未設定の変数の展開をエラーにします（ステータス 1。対話でないシェルは終わり、対話シェルはその行をやめる）。 |
| `-x` | `xtrace` | 単純なコマンドごとに、その前に `$PS4`（既定は `+ `）と、展開した代入と単語を標準エラー出力に書きます。`A-Za-z0-9_./=:@%+-` 以外の文字を含む単語はシングルクォートで囲みます。 |
| `-f` | `noglob` | パス名展開をしません。 |
| `-a` | `allexport` | 代入した変数をすべてエクスポートします。 |
| — | `pipefail` | パイプラインのステータスを、失敗したいちばん右の要素のものにします。 |

ほかの文字や `-o` の名前は受け付けて無視します（たとえば `set -v`、`set -o vi`、`set -n` は効果がありません）。
引数なしの `set` は、すべての変数を `name='value'` の形で、並べ替えて表示します。`set -- args` と `set args`
（最初の引数が `-`/`+` で始まらない）は位置パラメータを置き換えます。

## 対話モード

### プロンプト

シェルは各コマンドの前に、プロンプトを標準エラー出力に書きます。`PS1` が設定されていれば、次のエスケープだけを
置き換えます: `\w`（作業ディレクトリ。`$HOME` は `~` と表示）、`\u`（常に `user`）、`\h`（ホスト名 `openvessel`）、
`\$`（`$`）。`PS1` が未設定なら、プロンプトは次のとおりです。

```text
\e[1;32muser@openvessel\e[0m:\e[1;34m~/app\e[0m$ 
```

つまり、緑の `user@openvessel`、コロン、青の作業ディレクトリ、`$ ` です。行が文法的に完結していないとき（閉じて
いないクォート、`fi` の無い `if`、行末の `|`）は、`> ` を出して次の行をつなげます。

入力したコマンドについて: 空の行は無視します。エラーは `sh: <message>` と表示してステータスを設定します。`exit`
か入力の終わりでシェルは終わります（入力の終わりでは `exit` と表示し、直前のステータスを返します）。`${p:?}` と
`set -u` のエラーでは、対話シェルは終わりません。

### 行編集

TTY の上では、シェルは 1 行を読む間、端末をエコーなしの raw モードにし、読み終えたら（前面のプログラムが
終わった後も）エコーありの cooked モードに戻します。

| キー | 動作 |
|---|---|
| Enter（CR または LF） | 行を確定 |
| ← / → | 1 文字移動 |
| ↑ / ↓ | 前 / 次の履歴（編集中の行は取っておきます） |
| Home、Ctrl-A | 行頭へ（Home: `ESC [ H`、`ESC O H`、`ESC [ 1 ~`） |
| End、Ctrl-E | 行末へ（End: `ESC [ F`、`ESC O F`、`ESC [ 4 ~`） |
| Backspace（DEL または Ctrl-H） | カーソルの前の文字を消す |
| Delete（`ESC [ 3 ~`） | カーソルの位置の文字を消す |
| Ctrl-D | 空の行なら入力の終わり。そうでなければカーソルの位置の文字を消す |
| Ctrl-K | 行末まで消す |
| Ctrl-U | 行頭まで消す |
| Ctrl-W | カーソルの前の単語を消す（単語は空白で区切る） |
| Alt-B、Ctrl-← | 1 単語左へ |
| Alt-F、Ctrl-→ | 1 単語右へ |
| Ctrl-L | 画面を消して行を描き直す |
| Ctrl-C | `^C` を表示し、行を捨て、ステータスを 130 にして、新しいプロンプトを出す |
| Tab | 補完（下を参照） |

ほかの制御文字は無視します。TTY が無いとき（パイプから入力した `sh -i`）は、ただのテキストとして行を読み、
プロンプトはやはり標準エラー出力に書きます。

### 履歴と補完

- 履歴はシェルが動いている間だけメモリに持ちます（ファイルには保存しません）。直前の項目と同じ行は追加しません。
  `history` で番号付きで表示します。
- Tab はカーソルの前の単語を補完します。行の最初の単語（`/` を含まない）では、組み込みコマンドの名前、関数の
  名前、`PATH` のディレクトリにあるすべてのファイルの名前が候補です。それ以外では、作業ディレクトリから見た
  ファイル名です（`~/` も分かります）。隠しファイルは、打った部分が `.` で始まるときだけ候補になります。
  ディレクトリには `/` が付きます。
- 候補が 1 つなら、それを入れて空白を付けます（ディレクトリの後には付けません）。複数なら共通の先頭部分を入れ、
  何も足せなかったときは候補を行の下に並べます。

### シグナル

対話シェルは SIGINT・SIGTSTP・SIGQUIT・SIGWINCH を無視します（trap したときを除く）。起動したジョブ（プログラム、
またはパイプラインのすべてのプログラム）はそれぞれ自分のプロセスグループを持ち、ジョブが動いている間はそのグループ
が端末の前面のグループになります。そのため Ctrl-C はシェルではなくジョブに届きます。TTY については
[プロセス](processes.ja.md) を参照してください。

### trap

`trap 'action' SIGNAL...` でハンドラを設定します。`trap '' SIGNAL` はシグナルを無視し、`trap - SIGNAL` は既定に
戻します。シグナルは `SIG` の有無を問わない名前（`INT`、`SIGTERM`）か番号で、`EXIT`（または `0`）と `ERR` は
疑似シグナルです。

- `EXIT` は、シェルが終わるとき（入力の終わり、`exit`、`set -e`、シェルを終わらせるエラー）とシグナルで死ぬ前に
  動きます。サブシェルでは、サブシェルが終わるときに動きます。動作の中の `exit` が最終的なステータスになり、動作の
  中の `$?` は終了ステータスです。
- `ERR` は、`set -e` が当てはまる場所でコマンドが失敗した後に動きます。
- シェルが受け取った trap 済みのシグナル（`kill` や端末の ^C）は、次のコマンドの区切りで trap の動作を実行し、`wait` を
  中断します。無視したシグナルは捨てます。trap していない SIGTERM・SIGHUP などは、対話でないシェルを（`EXIT` の
  trap の後に）128 + n で終わらせます。
- オペランドなしの `trap` や `trap -p [SIGNAL...]` は、ハンドラを `trap -- 'action' SIGNAME` の形で表示します。
  `trap -l` はシグナルの一覧を出します。

## 組み込みコマンド

### echo

```text
echo [-n] [-e] [-E] [arg...]
```

先頭の引数のうち、`-` の後に `n`・`e`・`E` の文字だけが続くものがオプションです（`-ne`、`-en`、`-nE`）。`-n` は
最後の改行を出しません。`-e` でエスケープを有効にし、`-E` で無効にします（既定）。`--` はふつうの引数として
出力します。`-e` のときのエスケープ: `\a \b \e \f \n \r \t \v \\`、`\0nnn`（8 進、3 桁まで）、`\xHH`。`\c` で
出力を止めます（改行も出しません）。

### printf

```text
printf [-v var] format [argument...]
```

- 変換: `%d %i`（整数。切り捨て）、`%u`（絶対値）、`%o`、`%x`、`%X`、`%e %E`（JavaScript の指数の形。たとえば
  `1.234500e+3`）、`%f %F`、`%g %G`、`%c`（最初の 1 文字）、`%s`、`%b`（バックスラッシュのエスケープを解釈した
  引数）、`%q`（シェル用にクォート）、`%%`。
- フラグ: `-`（左寄せ）、`0`（数を 0 で埋める）、`+` と空白（`%d`/`%i` の符号）、`#`（`%x` にだけ `0x` を付ける）。
  幅と精度は数か `*`。精度は `%s`/`%b` を切り詰めます。
- 書式の中のエスケープ: `\a \b \e \f \n \r \t \v \\ \" \'`、`\NNN` と `\0NNN`（8 進）、`\xHH`、`\c`（出力を止める）。
- 数の引数: `'c` や `"c` は文字コードになります。数でない文字列は `parseFloat` で読み、それでもだめなら 0 です。
  エラーにはなりません。
- 引数が残っている間、書式を繰り返し使います。足りない引数は空 / 0 です。
- `-v var` は、出力する代わりに結果を `var` に入れます。書式が無いと `usage: printf format [arguments]` で
  ステータス 2。

### read

```text
read [-r] [-p prompt] [-d delim] [-n count] [-N count] [-s] [-t x] [-u x] [-a x] [name...]
```

- fd 0 から区切り（既定は改行）まで 1 バイトずつ読み、その後 UTF-8 として解読します。
- `-r` が無ければ、`\` は次の文字をエスケープし、`\` と改行の組は行を続けます。
- `-p` はプロンプトを標準エラー出力に書きます。`-d ''` は NUL を区切りにします。`-n`/`-N` は `count` バイトで
  止めます。`-s` は受け付けますが効果はありません。`-t`・`-u`・`-a` は引数を 1 つ取り、無視します。
- 名前なし: 行全体を、前後を削らずに `REPLY` に入れます。名前 1 つ: 前後の IFS の空白を除いた行を入れます。
  名前が複数: 行を IFS の文字で分け、最後の名前に残り全部を入れます。
- 何も読めないまま入力が終わるとステータス 1 です（改行の無い最後の行は 0 を返します）。

### getopts

```sh
while getopts "ab:" opt; do
  case $opt in
    a) echo "flag a" ;;
    b) echo "b=$OPTARG" ;;
    ?) exit 2 ;;
  esac
done
shift $((OPTIND - 1))
```

`args`（既定は位置パラメータ）を `OPTIND`（既定は 1）から解析します。`optstring` で後ろに `:` の付いたオプションは
引数（続けて書いたものか次の単語）を取り、`OPTARG` に入れます。引数が無ければ `OPTARG` は空です。未知の
オプションでは、何も表示せずに `name` を `?` にします。最初のオプションでない引数、`-`、`--`（これは読み飛ばす）
で、`name` を `?` にしてステータス 1 を返します。

## プログラム

以下のプログラムは、特に書いていなければ `/bin` にあります。コマンドごとに断りが無ければ、オプションは
`src/kernel/coreutils.ts` の小さな getopt で解析します。

- 短いオプションはまとめられます（`-la`）。値を取るオプションは、続けて（`-n5`）も次の引数として（`-n 5`）も
  書けます。
- オプションは（GNU のプログラムと同じく）コマンドラインのどこにあっても、オペランドの後でも認識されます。`--` で
  終わります。別のコマンドを実行するプログラム（`xargs`・`env`・`timeout`・`nice`・`nohup`・`time`）は最初の
  オペランドで止まるので、コマンド自身のオプションはそのコマンドに届きます（`xargs stat -c %F`）。
- 数字もほかの文字と同じオプションの文字です（`ls -1`、`xargs -0`）。
- 未知のオプションは黙って受け付け、無視します。
- 長いオプションは、書いてあるものだけ対応します。`--name=value` で値を設定します。
- 読めないファイルのオペランドは `<cmd>: <file>: <reason>` と表示して次に進み、終了ステータスは 1 になります
  （`ls`・`grep`・`diff` は 2）。
- ファイルを読むコマンドでは、オペランドの `-` は標準入力です。
- ラッパー（`env`・`xargs`・`timeout`・`nice`・`nohup`・`time`）がコマンドを起動できなければ、無いときは 127、
  それ以外は 126 です。

### ls

```text
ls [-a] [-A] [-l] [-h] [-R] [-t] [-r] [-d] [-1] [--no-color] [file...]
```

| オプション | 長い形 | 効果 |
|---|---|---|
| `-a` | `--all` | `.` で始まる名前と、`.`・`..` も表示 |
| `-A` | `--almost-all` | `.` で始まる名前も表示（`.` と `..` は除く） |
| `-l` | `--long` | 長い形式 |
| `-h` | `--human` | 長い形式で大きさを `K`・`M`・`G`・`T`（1024 の累乗。10 未満は小数 1 桁）で表示 |
| `-R` | `--recursive` | サブディレクトリも再帰的に表示 |
| `-t` | | 更新時刻の新しい順 |
| `-r` | | 順を逆に |
| `-d` | | ディレクトリの中身ではなく、ディレクトリ自身を表示 |
| `-1` | | 1 行に 1 つ |
| | `--no-color` | 色を付けない |

- 名前は `localeCompare` で並べます。標準出力が TTY でなければ 1 行に 1 つ、TTY なら端末の幅に合わせた段組み
  （上から下へ埋める）で、色を付けます。ディレクトリは太字の青、シンボリックリンクは太字のシアン、実行可能な
  ファイルは太字の緑です。
- 長い形式: `mode links user user size date name`。リンクには `-> target` が付きます。所有者とグループは常に
  `user` です。setuid・setgid・スティッキーのビットは `s`/`S`/`t`/`T` で表します。日付は今から 180 日以内なら
  `Mon dd HH:MM`、それ以外は `Mon dd  YYYY`。ディレクトリの中身の一覧の前に `total` の行（ファイルごとに KiB に
  切り上げた大きさの合計）が付きます。ファイルのオペランドには付きません。
- 無いオペランドは `ls: cannot access 'x': No such file or directory` で、ステータス 2。

### cat

`cat [-n] [file...]` はファイルをつないで標準出力に書きます。オペランドなしか `-` では、標準入力をチャンク単位で
出力します（パイプの先の読み手には、データが届いた時点で見えます）。`-n` はすべての行に番号を付けます（`%6d<TAB>`）。

### head と tail

```text
head [-n N | -N | -n -N] [-c N] [file...]
tail [-n N | -N | -n +N] [-c N] [-f] [file...]
```

- `head`: 最初の `N` 行（既定は 10）か `N` バイト。`-n -N` は最後の `N` 行を除いたすべて。数が負でなければ、
  標準入力からは必要な行を読んだ時点で読むのをやめるので、`yes | head -1` は終わります。複数のファイルでは、
  それぞれの前に `==> name <==` が付きます。
- `tail`: 最後の `N` 行（既定は 10）、`+N` なら `N` 行目から。`-c N` は最後の `N` バイト、`-c +N` は `N` バイト目
  から。`tail` はまず入力をすべて読みます。複数のファイルでは、それぞれの前に `==> name <==` が付きます（`-q` では
  付きません）。改行の無い最後の行は、改行なしで出力します。
- `tail -f file`（ファイル 1 つだけ）: 表示した後、250 ms ごとにファイルを調べ、増えた分を止められるまで表示
  します。ファイルが小さくなったら、新しい末尾から続けます。

### wc

`wc [-l] [-w] [-c] [-m] [file...]`。オプションなしでは行数・単語数・バイト数です。`-m` は 3 列目をバイトではなく
文字（コードポイント）の数にします。単語は空白でない文字の並びです。列はいちばん長い数に合わせて右寄せします。
標準入力だけを読んだときは、詰めずに数を表示します。入力が 2 つ以上なら `total` の行が付きます。

### grep

```text
grep [options] pattern [file...]
grep [options] -e pattern... [-f file]... [file...]
egrep ...    fgrep ...
```

| オプション | 長い形 | 効果 |
|---|---|---|
| `-i`、`-y` | `--ignore-case` | 大文字と小文字を区別しない |
| `-v` | `--invert-match` | 合わない行を選ぶ |
| `-n` | `--line-number` | 行番号を付ける |
| `-c` | `--count` | ファイルごとに選んだ行の数を表示 |
| `-l` / `-L` | `--files-with-matches` / `--files-without-match` | 合った / 合わなかったファイルの名前だけを表示 |
| `-q` | `--quiet`、`--silent` | 出力なし。ステータスだけ |
| `-s` | `--no-messages` | 受け付けるだけ |
| `-w` | `--word-regexp` | 単語全体に合わせる（前後が単語の文字でない） |
| `-x` | `--line-regexp` | 行全体に合わせる |
| `-o` | `--only-matching` | 空でない一致を 1 行ずつ表示 |
| `-G` / `-E` / `-F` / `-P` | `--basic-regexp` / `--extended-regexp` / `--fixed-strings` / `--perl-regexp` | パターンの書き方（`-P` は JavaScript の `RegExp` の書き方） |
| `-r` / `-R` | `--recursive` / `--dereference-recursive` | ディレクトリを再帰的に探す（既定は `.`）。`-r` は途中のシンボリックリンクを飛ばし、`-R` はたどる |
| `-h` / `-H` | `--no-filename` / `--with-filename` | ファイル名を付けない / 常に付ける |
| `-a` | `--text` | バイナリのファイルもテキストとして扱う |
| `-e PAT` | `--regexp=PAT` | パターン。何度でも書けます |
| `-f FILE` | `--file=FILE` | ファイルからパターンを 1 行に 1 つ読む（`-` は標準入力） |
| `-m N` | `--max-count=N` | ファイルごとに、選んだ行が `N` 行になったら止める |
| `-A N`、`-B N`、`-C N` | `--after-context`、`--before-context`、`--context` | 一致の後 / 前 / 前後の `N` 行も表示 |
| | `--include=GLOB`、`--exclude=GLOB`、`--exclude-dir=GLOB` | `-r` のとき、ファイルとディレクトリをベース名で絞る（何度でも書けます） |
| | `--color…` | 受け付けて無視 |

- どれかのパターンに合えば、その行を選びます。パターンのオペランドには、改行で区切って複数のパターンを書けます。
- POSIX の正規表現を JavaScript の `RegExp` に変換します。基本の書き方（既定）では `\(` `\)` `\{` `\}` `\|` `\+`
  `\?` が演算子で、`\` の無いものは文字そのもの、先頭の `*` も文字そのものです。`-E` は拡張の書き方です。文字クラス
  を含む括弧式（`[[:digit:]]`、`[[:alpha:]]` など）と GNU のエスケープ `\w` `\W` `\s` `\S` `\b` `\B` `\<` `\>` が
  使えます。正しくないパターンは `RegExp` のエラーを表示してステータス 2。
- ファイルが 2 つ以上か `-r` のとき、ファイル名を付けます。ファイルのオペランドが無いとき、`.` の下の名前は `./`
  を付けずに表示します。
- 前後の行は、ファイル名と行番号の後に `:` ではなく `-` を付けて表示します。連続していないグループの間には
  `--` が入ります。
- NUL のバイトを含むファイルは `Binary file NAME matches` と表示します（`-a` が無ければ）。
- 終了ステータス: 選んだ行があれば 0、無ければ 1、読めないファイルがあれば（ほかの行を選んでいても）2。ただし
  `-q` は一致があればすぐ 0 を返します。

### sed

```text
sed [-n] [-E|-r] [-i[SUFFIX]] [-e script]... [-f file] [script] [file...]
```

| オプション | 効果 |
|---|---|
| `-n`、`--quiet`、`--silent` | パターンスペースを自動では表示しない |
| `-e script`、`--expression=script` | スクリプトを足す（複数あれば改行でつなぐ） |
| `-f file`、`--file=file` | ファイルからスクリプトを読む |
| `-E`、`-r`、`--regexp-extended` | 拡張の正規表現 |
| `-i[SUFFIX]`、`--in-place[=SUFFIX]` | ファイルをその場で書き換える。接尾辞があれば、バックアップを `file+SUFFIX` に残す（接尾辞は続けて書く: `-i.bak`） |
| `-s`、`-u`、`-z` | 受け付けて無視する |

`-e`/`-f` が無ければ、最初のオペランドがスクリプト、残りがファイルです。オプションはまとめても（`-ne`、`-Ei`）、
どこに書いてもかまいません。未知のオプションは `sed: invalid option -- 'x'` でステータス 1 です。`-i` が無ければ、
すべての入力をつないで 1 つの流れとして処理します。

アドレス: 行番号 `N`、`$`（最後の行）、`/regex/`（または別の区切りで `\cregexc`）。どれも後ろに `I` を付けると
大文字と小文字を区別しない正規表現になります。`addr1,addr2` は範囲を選びます（`addr2` が今の行以下の行番号なら
1 行だけ）。アドレスの後の `!` は否定です。

| コマンド | 効果 |
|---|---|
| `s/re/repl/flags` | 置換。区切りは任意（各部分の中では `\/` のようにエスケープ）。フラグ: `g`（すべて）、`N`（N 番目の一致だけ。1 桁）、`p`（置換したら表示）、`i`/`I`（大文字と小文字を区別しない）。`repl` の中では `&` = 一致した部分、`\1`〜`\9` = グループ、`\&` = `&` そのもの、`\n` `\t` と下のエスケープ、`\U` `\L`（`\E` まで大文字 / 小文字）、`\u` `\l`（次の 1 文字）。 |
| `y/abc/xyz/` | 文字の置き換え |
| `d` | 行を消し、次のサイクルへ |
| `p` | 行を表示 |
| `=` | 行番号を表示 |
| `q` | （`-n` でなければ）表示して終わる |
| `a text`、`a\` + 改行 + `text` | 行の後に文字列を足す |
| `i text` | 行の前に文字列を入れる |
| `c text` | 行を文字列に置き換える |

コマンドは `;` か改行で区切ります。正規表現は `grep` と同じ POSIX→JavaScript の変換に、GNU sed のエスケープ
`\n` `\t` `\r` `\f` `\v` `\a`・`\dNNN`・`\oNNN`・`\xHH`・`\cX` を加えたものです。対応していないもの:
`{ }` のブロック（中かっこは無視されるので、中のコマンドはすべての行に適用されます）、`n N P D h H g G x b t T r w l`、
`0,/re/`、`addr,+N`、`first~step`。改行の無い最後の行は、改行なしで出力します。

```sh
sed -i 's/"dev": ".*"/"dev": "astro dev"/' package.json
sed -n '/^## /p' README.md
sed -E 's/([0-9]+)\.([0-9]+)/\2.\1/g' versions.txt
```

### find

```text
find [path...] [expression]
```

パスは、先頭から続く `-` で始まらず `!` でも `(` でもない引数です。既定は `.`。項目は並べ替えた順に深さ優先で
たどり、シンボリックリンクはたどりません。結果は、渡したパスに相対の名前を足した形で表示します（`./src/a.js`）。

| 式 | 意味 |
|---|---|
| `-name PAT`、`-iname PAT` | ベース名がシェルのパターンに合う（大文字と小文字を区別しない） |
| `-path PAT`、`-wholename PAT` | 表示するパス全体が合う（`*` は `/` にも合う） |
| `-type T` | `f` ふつうのファイル、`d` ディレクトリ、`l` シンボリックリンク、`p` FIFO、`s` ソケット、`c` / `b` キャラクタ / ブロックデバイス。カンマの並び（`f,d`）はどれかに合う |
| `-maxdepth N`、`-mindepth N` | 全体の深さの制限（どこに書いても同じ） |
| `-empty` | 空のふつうのファイルかディレクトリ |
| `-newer FILE` | `FILE` より後に更新された |
| `-size [+-]N[ckMG]` | 大きさ。単位は 512 バイト（既定）、`c` バイト、`k` KiB、`M` MiB、`G` GiB。`+` は大きい、`-` は小さい、無ければ切り上げて等しい |
| `-true`、`-false` | |
| `-print`、`-print0` | パスに改行 / NUL を付けて表示 |
| `-prune` | このディレクトリの中に入らない |
| `-delete` | 消す（ディレクトリは中身ごと） |
| `-exec CMD {} ;`、`-exec CMD {} +` | `{}` をパスに置き換えて `CMD` を実行する。`+`（単独の `{}` の後）では、すべてのパスで 1 回実行する |
| `!`、`-not`、`( )`、`-a`、`-and`、`-o`、`-or` | 演算子。並べて書くと `-a` |

- `-print`・`-print0`・`-delete`・`-exec` が無ければ、式が真になった項目をすべて表示します。
- `-delete` と `-exec` は後回しになり、すべてたどり終えてから動きます（消すのは深いものから）。そのため述語と
  しての `-exec` は常に真です。`;` では、単語の中の `{}` も置き換えます（`"<{}>"`）。`-exec` のコマンドが 1 つでも
  失敗すればステータス 1。
- 未知の述語は `find: unknown predicate '-x'` でステータス 1。無い開始パスは `find: 'path': No such file or directory`
  でステータス 1。

### sort

```text
sort [-n] [-h] [-f] [-r] [-u] [-t SEP] [-k N] [-o FILE] [file...]
```

| オプション | 効果 |
|---|---|
| `-n`、`-h` | キーを `parseFloat` した数で比べる（数でなければ 0。`-h` も `K`/`M` の接尾辞は分かりません） |
| `-f` | 大文字と小文字を区別しない |
| `-r` | 逆順 |
| `-u` | 隣り合う同じ行を 1 つにする（行全体で比べる） |
| `-t SEP` | フィールドの区切り（既定は、行の前後を削った後の空白の並び） |
| `-k N` | `N` 番目のフィールドから行末までをキーにする（`-k2,2` や `-k2n` のような修飾は `-k2` として読みます） |
| `-o FILE` | `FILE` に書く |

比較は UTF-16 のコード単位の順です（ロケールによる照合はしません）。並べ替えは安定です。GNU のほかのオプション
（`-V`・`-c`・`-s`・`-z`・`-b`・`-M`）は無視します。

### uniq

`uniq [-c] [-d] [-u] [-i] [file]` は、隣り合う同じ行を 1 つにします。`-c` は数を前に付け（`%7d `）、`-d` は重複
した行だけ、`-u` は重複しない行だけを表示し、`-i` は大文字と小文字を区別しません。読むのは最初のオペランドだけで、
出力ファイルのオペランドは無視します。

### cut

`cut -f LIST [-d C] [file...]` はフィールドを選びます（既定の区切りは TAB）。`-c LIST` と `-b LIST` は文字を
選びます（どちらもバイトではなく文字で数えます）。`LIST` はコンマ区切りの `N`・`N-M`・`N-`・`-M` です。`-f` では、
区切りの無い行はそのまま表示し（`-s` はありません）、出力の区切りは入力の区切りと同じです。

### tr

`tr [-c] [-d] [-s] [-t] SET1 [SET2]` は標準入力だけを読みます。集合には範囲（`a-z`）、クラス `[:lower:]`
`[:upper:]` `[:digit:]` `[:space:]` `[:alpha:]` `[:alnum:]`、`\n \t \r \\` が使えます。

- 置き換え: `SET1` の各文字を、`SET2` の同じ位置の文字にします。`SET2` が短ければ最後の文字を繰り返します（`-t` は
  代わりに `SET1` を `SET2` の長さに切ります）。
- `-c` は `SET1` の補集合を使います。`SET2` があれば、`SET1` に無い文字をすべて `SET2` の最後の文字にし、`SET1` の
  文字はそのまま残します。
- `-d` は `SET1`（`-c` ならその補集合）の文字を消します。
- `-s` は同じ文字の並びを 1 つにまとめます。対象は、置き換えか削除のときは `SET2` の文字、それ以外は `SET1` の文字です。
- オペランドが足りなければ `tr: missing operand` でステータス 1。

```sh
echo "Hello" | tr a-z A-Z        # HELLO
tr -d '\r' < dos.txt > unix.txt
tr -cs '[:alnum:]' '\n' < in.txt   # 1 行に 1 単語
```

### xargs

```text
xargs [-0] [-d DELIM] [-a FILE] [-n N | -L N | -I STR] [-r] [-t] [-P N] [command [arg...]]
```

- オプションはコマンドで終わります。その後ろはすべてコマンドに渡ります（`xargs stat -c %F`）。
- 標準入力（`-a` なら `FILE`）をすべて読み、空白と改行で項目に分けます。シングルクォート・ダブルクォート・
  バックスラッシュは空白を守ります（`'a b'` は 1 つの項目。閉じていないクォートはエラー）。`-0` では NUL で、`-d`
  では指定した文字（`\n`・`\t` なども使えます）で区切り、どちらもクォートは処理しません。
- `command`（既定は `echo`）に項目を付けて実行します。一度にすべて、または `-n` / `-L` で `N` 個ずつです（`-L` は
  行ではなく項目を数えます）。
- `-I STR`（`-i` は `-I {}`）: 入力の 1 行（先頭の空白は除く）ごとに 1 回実行し、引数の中の `STR` をすべて置き換えます。
- `-r`: 項目が無ければコマンドを実行しません（`-r` が無いときは、項目なしで 1 回実行します）。`-t` は各コマンド行を標準エラー
  出力に書きます。`-P` は受け付けますが、コマンドは常に 1 つずつ動きます。
- ステータス: どれかが 1〜125 で終われば 123、255 で終われば 124（そこで止まる）、シグナルで止められたら 125、
  コマンドが無い / 実行できないときは 127 / 126。

```sh
find . -name '*.log' -print0 | xargs -0r rm -f
```

### cp, mv, rm, ln

- `cp [-r|-R|-a] [-n] [-P|-d] SRC... DEST`: 元が複数なら `DEST` はディレクトリでなければなりません。`-r`/`-R`/`-a`
  なしでディレクトリを渡すと `cp: -r not specified; omitting directory 'x'`。`-n` は、あるファイルを飛ばします。
  元のファイルとして渡したシンボリックリンクは、`-a`・`-P`・`-d` が無ければリンク先のファイルとしてコピーします。
  コピーするディレクトリの中のリンクはリンクのままです。`-a` は「リンクをたどらない再帰」の意味で、ほかの `-a` の
  意味（所有者・時刻）は `cp` 自身では実装していません。
- `mv [-n] SRC... DEST`: 名前を変えます。ディレクトリでない既存の対象は置き換えます。`-f`・`-i`・`-v` は無視します。
- `rm [-r|-R] [-f] [-d] [-v] FILE...`: `-r` はディレクトリを中身ごと、`-d` は空のディレクトリを消します。`-f` は
  無いファイルとオペランドの不足を無視し、`-v` は `removed 'x'` を表示します。GNU の rm の既定の
  `--preserve-root` と同じく、`rm -r /` は断り（`it is dangerous to operate recursively on '/'`、ステータス 1）、
  `.` と `..`（`dir/.` も）も断ります。確認はしません（`-i` は無視）。
- `ln [-s] [-f] [-n] TARGET [LINK]`: 既定はハードリンク、`-s` でシンボリックリンク。`LINK` が無ければ、作業
  ディレクトリに対象のベース名で作ります。`LINK` がディレクトリなら（`-n` が無ければ）その中に作ります。`-f` は
  既存の `LINK` を先に消します。使うのは最初の 2 つのオペランドだけです。

### chmod

`chmod [-R] [-c] [-f] [-v] MODE FILE...`。`MODE` は 8 進（`755`）か、`[ugoa]*[+-=][rwxXst]*` または
`[ugoa]*[+-=][ugo]`（ほかのクラスのビットをコピーする: `g=u`）のコンマ区切りの並びです。

- `+` と `-` は指定したクラスのビットを足し / 消し、`=` は指定したクラスだけを設定してほかはそのままにします
  （`755` に `chmod u=rw f` で `655`）。
- クラスの文字が無ければ、umask で隠されたものを除くすべてのクラスに適用します（umask が `022` なら、`chmod +w f`
  は所有者の書き込みのビットだけを足します。`a+w` なら 3 つとも）。
- `X` は、ディレクトリか、すでに実行のビットのあるファイルにだけ実行のビットを立てます。`s` と `t` は setuid /
  setgid とスティッキーのビットを立てます。
- `-x` や `-w,+r` のようなモードは、オプションではなくモードです。
- `-R` は再帰します。途中のシンボリックリンクは変えず、たどりもしません。`-c`・`-f`・`-v` は受け付けます。
- 正しくないモードは `chmod: invalid mode: 'x'` でステータス 1。

### stat

`stat [-L] [-c FORMAT | --printf FORMAT] [-t] FILE...` と `stat -f FILE...`。`-L` が無ければリンクはたどりません。
既定の出力は GNU の形で、時刻はローカルのタイムゾーン（`TZ`）です。

```text
  File: f.txt
  Size: 18              Blocks: 1          IO Block: 4096   regular file
Device: 801h/2049d	Inode: 139         Links: 1
Access: (0644/-rw-r--r--)  Uid: ( 1000/    user)   Gid: ( 1000/    user)
Access: 2026-10-26 15:11:32.702000000 +0900
Modify: 2026-10-26 15:11:32.702000000 +0900
Change: 2026-10-26 15:11:32.702000000 +0900
 Birth: 2026-10-26 15:11:32.702000000 +0900
```

`-c FORMAT` の並び: `%n` 名前、`%N` クォートした名前（リンクには `-> target`）、`%s` 大きさ、`%b` ブロック数、`%B`
512、`%o` I/O ブロック、`%a` 8 進のモード、`%A` モードの文字列、`%f` モードそのもの（16 進）、`%F` ファイルの種類
（`regular file`・`regular empty file`・`directory`・`symbolic link`・`fifo`・`socket`・`character special file`・
`block special file`）、`%h` リンク数、`%i` inode、`%d`/`%D` デバイス（10 進 / 16 進）、`%t`/`%T` デバイスの
メジャー / マイナー（16 進）、`%u`/`%g` uid / gid、`%U`/`%G` `user`、`%x %y %z %w` アクセス / 変更 / 状態変更 /
作成の時刻、`%X %Y %Z %W` その秒数、`%%`。ほかの並びは `?` になります。改行を付けます。`--printf` は改行を付けず、
`\n`・`\t`・`\\` を解釈します。`-t` は短い 1 行の形です。

`-f` はファイルシステムについて表示します。メモリ上のファイルシステム 1 つで、種類は `tmpfs`、ブロックの大きさは
4096、ブロックは 1048576 個ですべて空きです。`-c` では `%n %T %t %s %S %b %f %a %c %d %l %i` が使えます。

### du

`du [-s] [-h] [-a] [-d N|--max-depth=N] [path...]`。ディレクトリは 4096 バイトと中身の合計、ファイルは大きさで数え
ます。値は KiB に切り上げたもの、`-h` なら人が読みやすい形です。ディレクトリは中身の後に表示します。`-a` は
ファイルも表示し、`-s` はオペランドだけを表示します。エラーは表示しますが、ステータスは常に 0 です。

### date

```text
date [-u] [-d STRING | -r FILE] [-I[FMT] | -R | +FORMAT]
```

タイムゾーンは `TZ`（IANA の名前 `Asia/Tokyo`、POSIX の形 `JST-9`・`EST5`、UTC なら `''`）で、`TZ` が未設定なら
ブラウザのタイムゾーンです。`-u` は UTC を使います。タイムゾーンの略称は、`Intl` が出すもの（`EST`・`GMT`・
`UTC`）、`Intl` がオフセットでしか表さない主なタイムゾーンは内蔵の表（`JST`・`KST`・`CET`/`CEST`・`AEST` など）、
それ以外は tzdata と同じオフセットの形（`+0530`）です。

`-d @SECONDS` は Unix 時刻を使います。`now`・`today`・`tomorrow`・`yesterday` がわかります。`YYYY-MM-DD` と
`YYYY-MM-DD HH:MM[:SS]` はそのタイムゾーンのローカル時刻です。それ以外の文字列は JavaScript の `Date` で解析します。
解析できない日付は `date: invalid date 'x'` でステータス 1。`-r FILE` はファイルの更新時刻を使います。書式が無ければ
GNU の既定の `%a %b %e %H:%M:%S %Z %Y`（`Mon Oct 26 16:12:57 JST 2026`）で出力します。`-I` は ISO 8601（`date`・
`hours`・`minutes`・`seconds`・`ns`）、`-R` は RFC 5322 の形です。

| 並び | 値 |
|---|---|
| `%Y` `%y` `%C` `%G` `%g` | 年、2 桁の年、世紀、ISO 週の年（4 桁 / 2 桁） |
| `%m` `%d` `%e` `%j` | 月、日、空白で埋めた日、年の通算日 |
| `%H` `%I` `%k` `%l` `%M` `%S` | 時（24 / 12 時間。`%k` `%l` は空白で埋める）、分、秒 |
| `%p` `%P` | `AM`/`PM`、`am`/`pm` |
| `%a` `%A` `%b` `%h` `%B` | 曜日と月の名前（C ロケール） |
| `%u` `%w` `%U` `%W` `%V` | 曜日（1〜7 / 0〜6）、年の週番号（日曜始まり / 月曜始まり / ISO） |
| `%s` `%N` | Unix 秒、ナノ秒（ミリ秒の精度。`%3N` で 3 桁） |
| `%F` `%T` `%D` `%R` `%r` `%c` `%x` `%X` | `%Y-%m-%d`、`%H:%M:%S`、`%m/%d/%y`、`%H:%M`、`%I:%M:%S %p`、`%a %b %e %H:%M:%S %Y`、`%m/%d/%y`、`%H:%M:%S` |
| `%z` `%:z` `%::z` `%Z` | `+0900`、`+09:00`、`+09:00:00`、タイムゾーンの略称 |
| `%n` `%t` `%%` | 改行、タブ、`%` |

`%` の後のフラグ: `-`（埋めない）、`_`（空白で埋める）、`0`（0 で埋める）、`^`（大文字）、`#`（大文字と小文字を
入れ替える）と幅（`%10s`）。ほかの並びはそのまま出力します。時計の設定には対応していません。

### diff

```text
diff [-u | -U N] [-q] [-s] [-i] [-w] [-b] [-a] [-L LABEL]... FILE1 FILE2
```

どちらのファイルも `-` なら標準入力です。同じならなにも出力せずステータス 0（`-s` は
`Files A and B are identical` を表示）。違えばステータス 1。問題があれば（無いファイル、ディレクトリ、
オペランドの誤り）ステータス 2。

- 既定（通常の形）: `2c2`・`4a5`・`1d0` のような変更の指示に続けて、古い行を `< ` 付きで、`---`、新しい行を `> `
  付きで表示します。
- `-u` / `-U N`: 前後 `N` 行（既定は 3）を付けた unified の形。見出しは `--- FILE1<TAB>更新時刻` / `+++ FILE2<TAB>更新時刻`
  （時刻は `2026-10-26 16:12:57.123000000 +0900` の形）か `-L` のラベルで、その後に `@@ -l,n +l,n @@` のハンク
  が続きます。2N 行より近い変更は同じハンクに入ります。
- 改行の無い最後の行の後には `\ No newline at end of file` が付き、改行のある同じ行とは違うものとして扱います。
- `-q` は `Files A and B differ` だけを表示します。`-i` は大文字と小文字、`-w` はすべての空白、`-b` は空白の量の
  違いを無視します。NUL のバイトを含むファイルは、`-a` が無ければ `Binary files A and B differ` です。
- 変更の手順は最小です（Myers のアルゴリズム）。とても違う大きな入力では、変わった真ん中の部分を丸ごと置き換える
  形に切り替えます。ディレクトリは比べません（`-r` はありません）。

### file

`file [-b] [-L] NAME...` は `directory`、`symbolic link to TARGET`（`-L` ならたどる）、`fifo (named pipe)`、
`socket`、`character special (M/m)`、`block special (M/m)`、`empty`、`data`（最初の 4096 バイトに NUL がある）、
`X script, ASCII text executable`（`#!` の行がある）、`Unicode text, UTF-8 text`、`ASCII text` のどれかを表示します。
`-b` は名前を付けません。エラーは ``NAME: cannot open `NAME' (reason)`` の形で標準出力に出し、ステータスは常に 0 です。

### mktemp

`mktemp [-d] [-t] [-p DIR] [TEMPLATE]` は、ファイル（モード `0600`、排他的に作成）か、`-d` ならディレクトリ
（モード `0700`）を作り、その絶対パスを表示します。`TEMPLATE`（既定は `tmp.XXXXXXXXXX`）の末尾の `X` は、ランダムな
`[a-z0-9]` の文字に置き換えます。ディレクトリは、`-p` なら `DIR`、`-t` かテンプレートが無ければ `$TMPDIR`（`/tmp`）、
それ以外は作業ディレクトリです。

### seq

```text
seq [-s SEP] [-w] [-f FORMAT] [FIRST [INCREMENT]] LAST
```

数は負（`seq -2 2 2`）でも小数でもかまいません。出力する数は `FIRST` と `INCREMENT` と同じ桁数の小数部を持ち
（`seq 0 0.1 0.3` は `0.0` 〜 `0.3`）、`FIRST + k*INCREMENT` で計算するので誤差がたまりません。`-s` は区切りです
（続けても離しても書けます: `-s,`、`-s ,`）。出力の最後は改行です。`-w` は 0 で埋めて幅をそろえます。`-f` には
`%f`・`%g`・`%e` の変換を 1 つ、フラグ・幅・精度付きで書けます（`%03g`）。正しくない数や 0 の増分はエラーで
ステータス 1。

### sleep

`sleep N[s|m|h|d]...` は引数の合計の時間だけ待機します（小数も可。既定の単位は秒。`inf` はシグナルを受けるまで待機）。正しくない
引数は `sleep: invalid time interval 'x'` でステータス 1。シグナルを受けると待機を終えます。

### チェックサム

`md5sum`・`sha1sum`・`sha256sum`・`sha512sum` は、入力ごとに `HEX  NAME` を表示します（標準入力は `-`）。SHA は
Web Crypto、MD5 は `@noble/hashes` で計算します。検査のモード（`-c`）はありません。エラーは結果より先に表示します。

### ps と kill

`ps` はオプションを取らず、動いているすべてのプロセス（カーネルのプログラムと Node.js のプロセス）について
`PID PPID CMD` を表示します。

`kill [-s SIGNAL | -n NUMBER | -SIGNAL | -NUMBER] [--] PID...`: 既定のシグナルは SIGTERM です。`-9`・`-KILL`・
`-SIGKILL`・`-s kill` は同じです。シグナル `0` は何も送らず、プロセスがあるかだけを調べます（ステータス 0、無ければ
`No such process` で 1）。PID `0` は呼び出し元のプロセスグループ、`-1` は `kill` 自身を除くすべてのプロセス、`-N` は
プロセスグループ `N` です（`kill -TERM -123` か `kill -- -123` と書きます）。`kill -l` はシグナルの名前を、`kill -L`
は番号付きの表を表示します。`kill -l 15` と `kill -l 143`（終了ステータス）は `TERM`、`kill -l TERM` は `15` を
表示します。未知のシグナルは `kill: X: invalid signal specification` でステータス 1、無い（終わった）プロセスは
`kill: (PID) - No such process` でステータス 1。シグナルそのものは [プロセス](processes.ja.md) で説明しています。

### env

```text
env [-i | -] [-u NAME]... [-C DIR] [-S STRING] [NAME=VALUE]... [command [arg...]]
```

コマンドが無ければ、できあがった環境変数を `NAME=VALUE` の行で表示します。`-i`/`-` は空の環境から始めます
（`NAME=VALUE` のオペランドだけが残ります）。`-u` は変数を消します（`-uNAME`、`--unset=NAME` も可）。`-C DIR` は
`DIR` でコマンドを実行します。`-S STRING` は残りを空白で分けます（`#!/usr/bin/env -S` のため）。起動できない
コマンドは `env: 'cmd': No such file or directory` でステータス 127（ほかのエラーなら 126）。

### time と timeout

`time command [arg...]` はプログラムを実行し（シェル関数や複合コマンドは実行できません。キーワードではなく
プログラムです）、その後、空の行に続けて `real\tMmS.SSSs` を標準エラー出力に書きます。`user` と `sys` の行は
ありません。ステータスはコマンドのものです。

```text
timeout [-s SIGNAL] [-k DURATION] [--preserve-status] [-v] DURATION command [arg...]
```

コマンドを実行し、`DURATION`（数に `s`・`m`・`h`・`d` の接尾辞を付けられます。`0` なら時間切れなし）の後に
`SIGNAL`（既定は SIGTERM）を送ります。オプションは `DURATION` で終わるので、コマンドは自分のオプションをそのまま
受け取ります（`timeout 5 sh -c '…'`）。`-k` は最初のシグナルからその時間が過ぎてもまだ動いていれば SIGKILL を
送ります。`-v` は送ったシグナルを標準エラー出力に書きます。ステータス: 時間切れなら 124（SIGKILL で止めたときは
137）、`--preserve-status` ならコマンド自身のステータス、それ以外はコマンドのステータスです。正しくない時間や
シグナルは 125、コマンドが無い / 実行できないときは 127 / 126。

### curl と wget

`curl` と `wget` は `/usr/bin` にあります。リクエストはカーネルによる通信のチェックとランタイムの fetch プロキシを通るので、
[ネットワークポリシー](network-policy.ja.md) が適用され、相手のサーバーはブラウザからのクロスオリジンのリクエストを
許していなければなりません。ブラウザが送れないリクエストは、ステータス 7 で失敗します。

```text
curl [options] URL
```

| オプション | 効果 |
|---|---|
| `-X M`、`--request M` | HTTP のメソッド |
| `-H "K: V"`、`--header` | リクエストのヘッダーを足す |
| `-d S`、`--data`、`--data-ascii`、`--data-binary`、`--data-raw` | リクエストの本文。複数あれば `&` でつなぎます。`@file` はファイルを読みます（`--data-raw` を除く）。`-d` は改行を取り除き、`--data-binary` は残します。`GET` を `POST` に変え、指定が無ければ `Content-Type: application/x-www-form-urlencoded` を付けます。 |
| `-G`、`--get` | `-d` のデータを `GET` のクエリ文字列として送る |
| `-A S`、`-e URL`、`-u USER:PW` | `User-Agent`、`Referer`（ブラウザが削除します）、Basic の `Authorization` ヘッダー |
| `-o FILE`、`--output` | 出力を `FILE` に書く（`-` は標準出力） |
| `-O`、`--remote-name` | 出力を URL のベース名（空なら `index.html`）に書く |
| `-I`、`--head` | `HEAD` のリクエスト。ステータス行とヘッダーだけを表示 |
| `-i`、`--include` | 本文の前にステータス行とヘッダーを表示 |
| `-D FILE`、`--dump-header` | ステータス行とヘッダーを `FILE`（`-` は標準出力）に書く |
| `-w FMT`、`--write-out` | 転送の後に `FMT` を表示: `%{http_code}`・`%{response_code}`・`%{url_effective}`・`%{content_type}`・`%{size_download}`・`%{method}`・`\n` |
| `-m S`、`--max-time` | `S` 秒で打ち切る（ステータス 28） |
| `-f`、`--fail` | HTTP ステータスが 400 以上なら、`curl: (22) The requested URL returned error: N` でステータス 22 |
| `-s`、`--silent` | エラーのメッセージを出さない（`-S` があれば出す） |
| `-S`、`-L`、`--location`、`-k`、`--insecure`、`-v`、`--compressed` とほかの長いオプション | 受け付けるだけで効果はありません（進み具合の表示はなく、リダイレクトは常にたどります） |

- 短いオプションはまとめられます。値を取るものは最後に置きます（`-fsSLo out.tgz`、`-XPOST`）。未知の短い
  オプションはエラー（ステータス 2）です。
- スキームの無い URL には `http://` を付けます。使う URL は 1 つだけ（オプションでない最後の引数）です。
- `-i`/`-I`/`-D` は `HTTP/1.1 <code> <text>` と、相手のサーバーのレスポンスヘッダー（ブラウザが見せる範囲）を表示します。
  これらはプロキシが `x-ov-*` のヘッダーで受け渡します。理由の文字列はサーバーのもので、サーバーが送らないとき
  （HTTP/2 など）はそのステータスの標準のものです。
- ブラウザがスクリプトに設定を許さないリクエストのヘッダー（`Cookie`・`Origin`・`Referer`・`Host`・`Accept-Encoding`・
  `Sec-*`・`Proxy-*` など）は、プロキシが削除します。Cookie は送りません。
- URL が無ければ `curl: no URL specified!` でステータス 2。通信のエラーや拒否されたリクエストは `curl: (7) <message>`
  でステータス 7。

`wget [-O FILE] URL` は `FILE`（`-O -` なら標準出力）に、既定では URL のベース名か `index.html` にダウンロード
します。中では `curl -fsSL` を実行するので、HTTP のエラーはステータス 22 です。ほかのオプションは無視します。
ただし、`-` で始まらない最初の引数（`-O` の値を除く）が URL として扱われる点に注意してください。
